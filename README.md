# Skill tree

A personal DevOps skill-tree tracker, rendered on a photo of a mini easel.
Multiple "canvases" (boards) live side by side and slide into focus when
you click one. Built with Next.js (App Router) + TypeScript + Tailwind,
with SQLite for persistence.

## Run it locally

```bash
npm install
npm run dev
```

Then open http://localhost:3000

## Files you don't need to read

These aren't hand-written - a tool generated them, and you'd never edit
them directly.

- **`package-lock.json`** - the exact version of every dependency (and
  their dependencies' dependencies), generated automatically by `npm
  install` whenever `package.json` changes. Never hand-edit this file;
  it exists so a second `npm install` on another machine installs the
  identical versions.
- **`node_modules/`** - the actual installed library code that
  `package-lock.json` describes. Generated by `npm install`, ignored by
  git (see `.gitignore`) since it can always be regenerated from
  `package.json`.
- **`.next/`** - Next.js's own build/cache output, generated every time
  you run `npm run dev` or `npm run build`. Also gitignored.
- **`next-env.d.ts`** - a small file Next.js generates so TypeScript
  knows about Next's built-in types. Regenerates itself; a comment at
  the top says as much.
- **`skilltree.db`** - not code at all, this is the actual SQLite
  database file. `lib/db.ts` creates it automatically the first time the
  server runs. Gitignored - it's your local saved progress, not part of
  the app.

## Config files - boilerplate, rarely touched

- **`package.json`** - the project's manifest: its name, the npm scripts
  (`dev`/`build`/`start`/`lint`), and the dependency list. Worth a skim
  so you know what's actually in play: Next.js, React, `better-sqlite3`,
  Tailwind.
- **`tsconfig.json`** - TypeScript compiler settings. Standard Next.js
  defaults; the one thing worth knowing is the `@/*` path alias, which
  is why imports look like `@/lib/db` instead of `../../lib/db`.
- **`next.config.js`** - Next.js's own config file. Currently empty
  (default) - nothing's been customised.
- **`tailwind.config.ts`** - tells Tailwind which files to scan for
  class names so it knows what CSS to generate. Default setup.
- **`postcss.config.js`** - wires Tailwind into the CSS build pipeline.
  Standard for any Tailwind project, never hand-edited.
- **`.gitignore`** - tells git which files/folders to never track
  (`node_modules`, `.next`, the `.db` file).
- **`.claude/launch.json`** - not part of the app. Tells Claude Code how
  to start the dev server when previewing changes.

## The actual app - read these, in this order

1. **`lib/skillTreeData.ts`** - the data model and the actual content.
   Defines the shapes (`SkillNode`, `SkillEdge`, `SkillBoard`,
   `NodeStatus`) and `skillBoards`, an array where each entry is one
   canvas: its `id`, `title`, and its `nodes`/`edges`. This is the
   single source of truth - pure data, no logic. Add a board here and it
   shows up in the carousel automatically.

2. **`app/layout.tsx`** - the root HTML wrapper every page renders
   inside (a Next.js App Router convention). Sets the browser tab title
   and wraps everything in `<html><body>`. You'll rarely touch this.

3. **`app/globals.css`** - pulls in Tailwind's generated CSS (the three
   `@tailwind` lines), plus one manual override: the page's base
   background colour.

4. **`app/page.tsx`** - the actual homepage. Deliberately thin: it just
   renders `<BoardCarousel />` inside a `<main>` with the background
   gradient. All the real logic lives further down this list.

5. **`components/Easel.tsx`** - renders *one* easel: the photo
   (`public/easel.png`) with a drop-shadow, and an absolutely-positioned
   overlay `div` sized to match the photo's actual white canvas
   rectangle (measured in pixel percentages, not guessed). Whatever's
   passed as `children` (a `<SkillTree>`) renders inside that overlay.
   This component doesn't know or care about boards, gating, or status -
   it's purely visual framing.

6. **`components/SkillTree.tsx`** - the biggest file and the one with
   all the interesting logic. Renders one board's tree as SVG (nodes as
   circles + text, edges as lines) and owns:
   - Loading/saving status and proof links via the board-scoped API
     (fetch on mount, `PATCH` on every change).
   - Prerequisite gating (`canComplete`/`getIncomingIds`) - a node can
     only be completed once every node pointing into it is already
     completed.
   - Hold-to-complete - press and hold for 650ms (a `setInterval`-driven
     progress ring) to toggle a node; un-completing has no gate.
   - The hover tooltip with the repo-link input, positioned left/right/
     above depending on the node so it doesn't cover a neighbour, with a
     short close-delay so your mouse has time to reach it.

7. **`components/BoardCarousel.tsx`** - owns the list of boards, which
   one is active, and the slide animation. Measures the active canvas's
   and the viewport's *real* pixel widths (via refs) and translates the
   whole row so the active one centers, with neighbours peeking at the
   edges. Clicking a non-active canvas switches to it. Also swaps the
   page's `<h1>` to match the active board's title.

8. **`lib/db.ts`** - opens (or creates) `skilltree.db`, creates the
   `node_status` table if it doesn't exist yet (`board_id` + node `id`
   together as the primary key), and seeds it once from each board's
   hardcoded starting statuses (`INSERT OR IGNORE`, so it never
   overwrites progress you've already saved).

9. **`app/api/status/[boardId]/route.ts`** - one HTTP endpoint: `GET
   /api/status/<board>` returns every saved node's status and proof link
   for that board, as JSON. This is what `SkillTree` fetches when a
   board first loads.

10. **`app/api/status/[boardId]/[id]/route.ts`** - one HTTP endpoint:
    `PATCH /api/status/<board>/<node-id>` updates one node's status
    and/or proof link. This is what `SkillTree` calls every time you
    hold-complete a node or edit its repo link.
